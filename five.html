(b)What is the numeric (octal) equivalent of rwxr-xr--? Show the calculation for each class.
(c)On RHEL 9, what is the default umask for a regular user and how does it affect newly created files and directories?

Section B

Practical Tasks

All tasks are compulsory  ·  Execute on your RHEL 9 EC2 instance
80 marks
⚠ Confirm your RHEL 9 instance is running and connected via SSH before starting. Call the evaluator to verify each task before moving on.
Part 1 — System Monitoring & Resource Assessment
P.01 RHELAssess the current health and resource state of the server 5 M
Tasks to complete
  • 01Confirm the OS version, kernel version, and system architecture using /etc/redhat-release, uname -r, and uname -m.
  • 02Show total, used, and available memory and swap in human-readable format using free -h.
  • 03List all mounted filesystems with disk usage and filesystem type using df -Th. Confirm that the root partition uses XFS.
  • 04Identify the top 5 processes by memory consumption using ps aux --sort=-%mem | head -6.
Part 2 — User, Group & Permission Management
P.02 usersProvision users and enforce access controls for a development team 8 M
Tasks to complete
  • 01Create two users: devuser and opsuser. Set passwords for both. Create a group named synnefo-team and add both users to it as secondary members. Verify membership with id devuser.
  • 02Create the directory /data/projects. Set its group ownership to synnefo-team and permissions to 2770 (SGID + rwx for owner and group). Verify with ls -ld /data/projects.
  • 03Switch to devuser using su - devuser and create a file inside /data/projects. Switch back and verify the file's group owner is automatically synnefo-team due to the SGID bit.
  • 04Grant opsuser full sudo privileges by creating /etc/sudoers.d/opsuser with the line opsuser ALL=(ALL) ALL. Verify with sudo -l -U opsuser.
  • 05Lock devuser's account with usermod -L devuser. Confirm the ! prefix in /etc/shadow. Unlock it with usermod -U devuser and verify the account is active again.
Part 3 — Process Management & systemd Services
P.03 systemdManage running processes and control system services on RHEL 9 7 M
Tasks to complete
  • 01Run sleep 500 & three times. List all three PIDs using ps aux | grep sleep. Kill the first by PID, the second using kill -9, and the third using pkill sleep. Verify none remain with ps aux | grep sleep.
  • 02Install Nginx using sudo dnf install nginx -y. Start the service and enable it to start automatically on boot. Verify both its running state and enabled state using systemctl status nginx.
  • 03Stop Nginx and verify it is stopped. Disable it from starting on boot and confirm it is disabled. Then start it again and verify the service is running.
  • 04Use systemctl list-units --type=service --state=failed to check for any failed services. Use journalctl -u <service-name> -n 20 --no-pager to inspect the logs of at least one service — active or failed.
Part 4 — Package Management with dnf
P.04 dnfManage software packages on a RHEL 9 server 5 M
Tasks to complete
  • 01Check for available package updates using dnf check-update. Report how many packages have pending updates — do not perform the upgrade.
  • 02Install net-tools and wget. Confirm both are installed using dnf info and note their version and repository source.
  • 03Remove wget completely. Verify it is no longer available using which wget.
  • 04List all packages explicitly installed by an administrator (excluding auto-installed dependencies) and save the output to /home/ec2-user/installed_packages.txt.
Part 5 — Scheduled Tasks (cron)
P.05 cronAutomate routine system administration tasks using cron 6 M
Tasks to complete
  • 01Create the script /home/ec2-user/heartbeat.sh that appends the current date-time and the output of free -h to /tmp/heartbeat.log. Make it executable with chmod +x.
  • 02Add a cron entry using crontab -e to run the script every 2 minutes. Wait for at least one execution, then show cat /tmp/heartbeat.log to the evaluator.
  • 03Create the file /etc/cron.d/disk_report with a system-wide cron entry that runs df -h as root every day at 23:30 and appends output to /var/log/disk_report.log. Remember: entries in /etc/cron.d/ require a username field before the command.
  • 04Confirm your user cron entry with crontab -l, then remove the heartbeat entry using crontab -e.
Part 6 — SSH & Key-Based Authentication
P.06 sshSet up key-based SSH access and harden the SSH daemon on RHEL 9 8 M
Tasks to complete
  • 01Generate a 4096-bit RSA key pair as ec2-user: ssh-keygen -t rsa -b 4096 -C "exam@synnefo". Accept the default storage path (/home/ec2-user/.ssh/id_rsa).
  • 02Manually deploy the public key for devuser: create /home/devuser/.ssh/, copy id_rsa.pub into /home/devuser/.ssh/authorized_keys, then set 700 on the directory and 600 on the file. Ensure both are owned by devuser:devuser.
  • 03Test key-based login: ssh -i /home/ec2-user/.ssh/id_rsa devuser@localhost. The session must open without a password prompt. Exit the session after confirming.
  • 04Edit /etc/ssh/sshd_config to set PermitRootLogin no, PasswordAuthentication no, and MaxAuthTries 3. Reload the daemon with systemctl reload sshd.
  • 05Verify all three settings took effect: sshd -T | grep -E "permitrootlogin|passwordauthentication|maxauthtries".
Part 7 — Web Server & Virtual Host
P.07 nginxDeploy and configure an Nginx virtual host on RHEL 9 10 M
Tasks to complete
  • 01Nginx was installed in P.03. Confirm it is running and enabled with systemctl status nginx. If not, start and enable it now.
  • 02Create the web root at /var/www/synnefoapp/html/. Place an index.html file containing <h1>Welcome to SynnefoApp</h1>. Set the entire directory tree ownership to nginx:nginx using chown -R.
  • 03Create the virtual host config at /etc/nginx/conf.d/synnefoapp.conf. It must listen on port 80, use server_name synnefoapp.local, point root to the web root above, and include separate access_log and error_log directives writing to /var/log/nginx/synnefoapp_access.log and /var/log/nginx/synnefoapp_error.log.
  • 04Test the config with nginx -t and reload Nginx. Add the line 127.0.0.1 synnefoapp.local to /etc/hosts.
  • 05Run curl -I http://synnefoapp.local. If you receive a 403 Forbidden, check the SELinux context on the web root with ls -lZ /var/www/synnefoapp/html/. Fix it with chcon -R -t httpd_sys_content_t /var/www/synnefoapp/html/ and retry. The response must show HTTP 200.
  • 06Make three requests to the site with curl http://synnefoapp.local. Confirm the access log is recording entries: tail /var/log/nginx/synnefoapp_access.log.
Part 8 — Network Access Control via AWS Security Groups
P.08 AWS SGManage inbound traffic rules using AWS Security Groups via the CLI 5 M
Tasks to complete
  • 01Install the AWS CLI with sudo dnf install awscli -y and configure it with your IAM credentials using aws configure. Verify the setup with aws sts get-caller-identity.
  • 02Get your instance's MAC address from the metadata service, then retrieve the Security Group ID: curl -s http://169.254.169.254/latest/meta-data/network/interfaces/macs/<MAC>/security-group-ids. Describe the group with aws ec2 describe-security-groups --group-ids <sg-id>.
  • 03Add an inbound rule to allow HTTP (TCP port 80) from 0.0.0.0/0 using aws ec2 authorize-security-group-ingress. Verify the rule is listed in the group's inbound rules.
  • 04Add a second inbound rule to allow MySQL (TCP port 3306) only from the CIDR 10.0.0.0/24, simulating a database port restricted to an internal subnet.
  • 05Revoke the port 3306 rule using aws ec2 revoke-security-group-ingress. Describe the Security Group again to confirm the rule is gone.
Part 9 — Disk & Storage Management
P.09 storageInspect storage layout and manage filesystems on RHEL 9 6 M
Tasks to complete
  • 01List all block devices using lsblk. Identify the primary disk and its partitions.
  • 02Display the current LVM layout using pvs, vgs, and lvs. Report the Volume Group name, total size, and free space available.
  • 03Create a new directory /mnt/examdata. Create a 200 MB image file at /tmp/testfile.img using dd if=/dev/zero of=/tmp/testfile.img bs=1M count=200. Format it as XFS with mkfs.xfs /tmp/testfile.img and mount it to /mnt/examdata using mount -o loop. Verify the mount with df -h /mnt/examdata.
  • 04Unmount /mnt/examdata cleanly using umount. Confirm it is no longer mounted with df -h.
Part 10 — Network Diagnostics
P.10 networkDiagnose network configuration and connectivity on RHEL 9 5 M
Tasks to complete — use nmcli and ip; ifconfig is deprecated on RHEL 9
  • 01List all network interfaces and their states using nmcli device status. Display IP addresses and MAC addresses with ip addr show.
  • 02Display the routing table using ip route show. Identify the default gateway and explain to the evaluator what happens to outbound traffic if this route is missing.
  • 03List all listening TCP ports and the process names bound to them using ss -tlnp. Identify which service is listening on port 80.
  • 04Test external connectivity by pinging 8.8.8.8 for 5 packets with ping -c 5 8.8.8.8 and trace the path with traceroute 8.8.8.8. Show both outputs to the evaluator.
Part 11 — Log Analysis
P.11 logsInvestigate system and service logs using journalctl on RHEL 9 6 M
Tasks to complete
  • 01Show all journal entries from the past 1 hour: journalctl --since "1 hour ago" --no-pager. Then filter to show only Nginx service entries from today: journalctl -u nginx --since today --no-pager.
  • 02SSH login events on RHEL 9 are recorded in /var/log/secure. Use grep to list all failed password attempts and display a count. Then find and display the last 5 successful logins from the same file.
  • 03Use journalctl -p err -b --no-pager to show all error-priority messages since the last boot. Identify and report any recurring patterns to the evaluator.
Part 12 — Troubleshooting Scenarios
P.12 debugDiagnose and resolve three real-world RHEL 9 system administration problems 10 M
Each scenario is worth 3–4 marks — show the broken state first, then demonstrate the fix
  • S1Nginx config broken (4M): Introduce a deliberate syntax error into /etc/nginx/conf.d/synnefoapp.conf — for example, remove a semicolon from a directive. Attempt to reload Nginx — it must fail. Use nginx -t and journalctl -u nginx -n 20 --no-pager to locate the exact error, fix it, then reload and confirm the service is back up with curl -I http://synnefoapp.local.
  • S2Port 80 conflict (3M): Run sudo ncat -l 80 & to occupy port 80 (install nmap-ncat first with dnf install nmap-ncat -y if needed). Nginx can no longer bind to port 80 and will fail to start. Use ss -tlnp to identify the process occupying port 80, terminate it by PID, and successfully start Nginx. Verify with systemctl status nginx.
  • S3SELinux blocking web content (3M): Copy a file from /tmp to /var/www/synnefoapp/html/test.html using cp, which carries over the source SELinux context. Attempt to fetch it with curl http://synnefoapp.local/test.html — it will return 403 Forbidden. Use ls -lZ to inspect the wrong context, then fix it with restorecon -Rv /var/www/synnefoapp/html/ and verify the file is now served correctly.
