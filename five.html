Section A

Theory Questions

Answer any 4 out of 5  ·  5 marks each
20 marks
Q.01 Explain the Linux file and directory permission model. What do read, write, and execute mean when applied to a directory specifically? What is the effect of SUID, SGID, and the Sticky Bit? 5 M
(a)Decode the permission string drwxrwsr-t. Identify which special bits are set and what each one protects.
(b)What is the numeric (octal) equivalent of rwxr-xr--? Show the calculation for each class.
(c)On RHEL 9, what is the default umask for a regular user and how does it affect newly created files and directories?
Q.02 What is systemd and how does it manage services on RHEL 9? Explain the concept of unit files, dependency ordering, and targets. How does it differ from the SysV init system it replaced? 5 M
(a)What is the difference between systemctl stop, systemctl disable, and systemctl mask? Give a real scenario where you would use each.
(b)On RHEL 9, where are vendor-supplied unit files stored versus administrator overrides? Which takes priority and why?
(c)A service fails on boot. What commands would you run to inspect the failure, and which journalctl field shows the process exit code?
Q.03 What is SSH key-based authentication? Explain how the public/private key handshake works and why it is more secure than password authentication. 5 M
(a)What is the role of authorized_keys on the server? What permissions must the .ssh directory and the file itself have, and why does SSH enforce this strictly?
(b)Name three directives you would change in sshd_config to harden an SSH server in production. State the risk each change mitigates.
(c)What does ssh-copy-id do? If you cannot use it, what manual steps must you perform to achieve the same result?
Q.04 What is LVM (Logical Volume Manager)? Explain the three-layer architecture — Physical Volumes, Volume Groups, and Logical Volumes — and the advantages it provides over traditional fixed partitioning. 5 M
(a)A RHEL 9 server is running out of space on /var. Describe step by step how to extend the logical volume and resize the XFS filesystem online without unmounting it.
(b)What is an LVM snapshot? Describe a real sysadmin scenario where you would create one before a risky operation.
(c)What is the difference between pvs, vgs, and lvs? What specific information does each command show?
Q.05 What is SELinux? Explain the difference between Enforcing, Permissive, and Disabled modes. Why does Red Hat strongly recommend keeping SELinux enabled in production? 5 M
(a)What is an SELinux context? Explain the four fields of the label system_u:object_r:httpd_sys_content_t:s0.
(b)A web server cannot read a file even though Unix permissions are correct. How would you diagnose whether SELinux is the cause, and how would you fix the file's context permanently?
(c)What is the difference between setenforce 0 and setting SELINUX=permissive in /etc/selinux/config? Which one survives a reboot?
Section B

Practical Tasks

All tasks are compulsory  ·  Execute on your RHEL 9 EC2 instance
80 marks
⚠ Confirm your RHEL 9 instance is running and connected via SSH before starting. Call the evaluator to verify each task before moving on.
Part 1 — System Monitoring & Resource Assessment
P.01 RHELAssess the current health and resource state of the server 5 M
  • 01Display the OS version, kernel version, and system architecture.
  • 02Show total, used, and available memory and swap in human-readable format.
  • 03List all mounted filesystems with their disk usage and filesystem type. Identify the filesystem type used on the root partition.
  • 04List the top 5 processes by memory consumption using only command-line tools — without an interactive process viewer.
Part 2 — User, Group & Permission Management
P.02 usersProvision users and enforce access controls for a development team 8 M
  • 01Create two users: devuser and opsuser. Set passwords for both. Create a group named synnefo-team and add both users to it as secondary members.
  • 02Create the directory /data/projects. Set its group ownership to synnefo-team and apply permissions that give the owner and group full access, deny others entirely, and ensure new files inside inherit the group.
  • 03Switch to devuser and create a file inside /data/projects. Switch back and verify that the file's group ownership was inherited automatically from the directory.
  • 04Grant opsuser full sudo privileges by creating a file in the appropriate sudoers drop-in directory. Verify the privileges are active.
  • 05Lock devuser's account. Confirm the lock is reflected in the shadow password file. Unlock the account and verify it is active again.
Part 3 — Process Management & systemd Services
P.03 systemdManage running processes and control system services on RHEL 9 7 M
  • 01Start three background sleep processes with a long duration. Confirm all three are running and note their PIDs. Kill the first by PID, the second with a force signal, and the third by process name. Verify none remain.
  • 02Install Nginx. Start the service, enable it to start automatically on boot, and verify both the running state and enabled state.
  • 03Stop Nginx and confirm it is stopped. Disable it from starting on boot and confirm it is disabled. Start it again and verify it is running.
  • 04Check for any failed services on the system. Inspect the logs of at least one service — active or failed — to show recent activity.
Part 4 — Package Management with dnf
P.04 dnfManage software packages on a RHEL 9 server 5 M
  • 01Check how many packages on the system have available updates. Do not perform the upgrade.
  • 02Install net-tools and wget. Confirm both are installed and note their version and repository source.
  • 03Remove wget completely and verify it is no longer available on the system.
  • 04List all packages explicitly installed by an administrator — excluding auto-installed dependencies — and save this list to /home/ec2-user/installed_packages.txt.
Part 5 — Scheduled Tasks (cron)
P.05 cronAutomate routine system administration tasks using cron 6 M
  • 01Write a shell script at /home/ec2-user/heartbeat.sh that appends the current date-time and free memory output to /tmp/heartbeat.log. Make the script executable.
  • 02Schedule the script to run automatically every 2 minutes for the current user. Wait for at least one execution and show the log file contents to the evaluator.
  • 03Create a system-wide scheduled job that runs a disk usage report as root every day at 23:30 and appends the output to /var/log/disk_report.log.
  • 04List your current user's scheduled jobs and confirm the entry is correct. Then remove it cleanly.
Part 6 — SSH & Key-Based Authentication
P.06 sshSet up key-based SSH access and harden the SSH daemon on RHEL 9 8 M
  • 01Generate a 4096-bit RSA key pair as ec2-user with the comment exam@synnefo. Use the default storage location.
  • 02Manually configure key-based SSH access for devuser — without using ssh-copy-id. Set all required file and directory permissions and ownership correctly.
  • 03Test that you can SSH into devuser@localhost using the key without being prompted for a password.
  • 04Harden the SSH daemon configuration: disable root login, disable password authentication, and limit authentication attempts to 3. Apply the changes without interrupting the current session.
  • 05Verify that all three hardening settings are active in the running SSH daemon configuration.
Part 7 — Web Server & Virtual Host
P.07 nginxDeploy and configure an Nginx virtual host on RHEL 9 10 M
  • 01Confirm Nginx is installed, running, and enabled. Nginx was installed in P.03 — verify its state before proceeding.
  • 02Create a web root at /var/www/synnefoapp/html/. Place an index.html file with a visible heading. Set correct ownership on the entire directory tree for the Nginx worker process.
  • 03Create a virtual host configuration file in the appropriate Nginx config directory. The server must listen on port 80, respond to the hostname synnefoapp.local, serve files from the web root, and write access and error logs to separate files under /var/log/nginx/.
  • 04Validate the Nginx configuration syntax and reload the service. Add a local DNS entry so the hostname resolves on this machine.
  • 05Send an HTTP request to http://synnefoapp.local and confirm a 200 OK response. If you receive a 403 Forbidden, investigate and resolve the cause before proceeding.
  • 06Make several requests to the site and confirm entries are being written to the access log.
Part 8 — Network Access Control via AWS Security Groups
P.08 AWS SGManage inbound traffic rules using AWS Security Groups via the CLI 5 M
  • 01Install the AWS CLI, configure it with your IAM credentials, and verify the identity of the configured account.
  • 02Retrieve the Security Group ID attached to your EC2 instance from the instance metadata service. Describe the Security Group and review its current inbound rules.
  • 03Add an inbound rule to allow HTTP traffic on port 80 from all sources. Confirm the rule appears in the Security Group.
  • 04Add a second inbound rule to allow MySQL traffic on port 3306 only from the internal CIDR block 10.0.0.0/24.
  • 05Remove the port 3306 rule. Describe the Security Group again and confirm the rule is no longer present.
Part 9 — Disk & Storage Management
P.09 storageInspect storage layout and manage filesystems on RHEL 9 6 M
  • 01List all block devices on the system. Identify the primary disk and its partitions.
  • 02Display the full LVM layout — Physical Volumes, Volume Groups, and Logical Volumes — including sizes and available free space in the Volume Group.
  • 03Create a 200 MB image file in /tmp, format it as an XFS filesystem, create a mount point at /mnt/examdata, and mount the image there. Verify the filesystem is mounted and accessible.
  • 04Unmount /mnt/examdata cleanly and confirm it is no longer mounted.
Part 10 — Network Diagnostics
P.10 networkDiagnose network configuration and connectivity on RHEL 9 5 M
  • 01List all network interfaces, their states, IP addresses, and MAC addresses. Use tools appropriate for RHEL 9 — ifconfig is deprecated.
  • 02Display the routing table and identify the default gateway. Explain to the evaluator what would happen to outbound traffic if this route were absent.
  • 03List all listening TCP ports with the name of the process bound to each. Identify which service is listening on port 80.
  • 04Test external connectivity to 8.8.8.8 with 5 ICMP packets and trace the full network path to the same address. Show both outputs to the evaluator.
Part 11 — Log Analysis
P.11 logsInvestigate system and service logs on RHEL 9 6 M
  • 01Show all system journal entries from the past hour. Then narrow the output to show only Nginx service entries from today.
  • 02Locate the file on RHEL 9 that records SSH authentication events. Extract all failed password attempts and display a count. Then find and display the last 5 successful logins.
  • 03Filter the system journal to show only error-priority messages from the current boot. Identify any recurring patterns and report them to the evaluator.
Part 12 — Troubleshooting Scenarios
P.12 debugDiagnose and resolve three real-world RHEL 9 system administration problems 10 M
  • S1Nginx config broken: Introduce a syntax error into the synnefoapp.conf virtual host file. Attempt to reload Nginx and show the evaluator that it fails. Diagnose the exact error, fix it, reload the service, and confirm the site is accessible again.
  • S2Port 80 conflict: Start a process that occupies port 80. Nginx will now fail to start. Identify the process holding the port, terminate it, and bring Nginx back up successfully.
  • S3SELinux blocking web content: Copy a file into the Nginx web root using a method that carries over the source file's SELinux context. Attempt to serve it — it will be denied. Diagnose the SELinux context mismatch and apply the correct context so the file is served successfully.
